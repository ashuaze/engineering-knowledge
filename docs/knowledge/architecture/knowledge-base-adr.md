# ADR-0001：用 Markdown 单一内容源组织工程知识

## 状态与范围

首版仓库采用本决策；对外发布配置仍待维护者选择。这是本知识库的实际结构记录，属于内容系统设计。

## 背景与约束

这套知识库面向软件开发、测试、运维与平台、数据、安全、架构及 AI 工程等方向的技术工程人员。维护者需要长期积累可复用的工程知识，希望内容可版本化、可迁移、可阅读，也能逐步发布成网站。初期文章数量有限，复杂服务的维护会挤占写作时间。

## 决策

以 Git 仓库内 Markdown 作为正文源；正文按主要领域存放，内容类型作为元数据。术语索引、领域页和文章目录从结构化数据及正文元数据生成；问题导航和学习路径由维护者策划。

初期在 GitHub 原生阅读，后续以 VitePress 渲染同一份 docs。当前仓库不依赖 VitePress 即可阅读和校验；发布配置见手册。

## 比较过的方案

| 方案 | 优点 | 对当前约束的代价 |
| --- | --- | --- |
| Markdown + Git | 差异清楚、可迁移、适合代码与校验 | 写作者需要熟悉 Git；跨页关联需维护 |
| 托管协作笔记平台 | 编辑和共享方便 | 导出、关系模型和发布效果受平台约束 |
| 自建 CMS / 数据库 | 灵活工作流和复杂查询 | 运维、权限和迁移占用额外时间 |

## 接受的后果

需要元数据约定、脚本与索引检查。手动策划入口仍需要编辑判断。默认 Markdown 不提供全文搜索、评论或访问统计；这些在站点阶段逐项加入。

## 重评条件

当出现多人频繁非技术编辑、复杂权限内容、审批链或现有文件模型无法解决的内容查询，再评估 CMS。若只是文章增加，先改导航和索引，不自动引入服务。

## 验收

任意正文能直接阅读；所有文章 ID 与关联有效；生成索引可重建；实验可运行；公开内容与个人记录边界明确。
