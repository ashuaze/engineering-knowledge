# 字符串匹配：失配怎样安全回退，位置又按什么计算

学习入口：日志里的关键字跨过两个读取块，为什么分别搜索两块却找不到？一次失配之后，从头比较能找到答案，但可能重复很多工作；直接跳过一大段，又可能漏掉合法出现。精确匹配需要先约定比较单位，再证明每次回退没有丢掉候选，最后把命中映射回读者需要的位置。

前置：[复杂度与分析口径](complexity-and-data-structures.md)、[线性结构与索引](sequences-stacks-queues-and-deques.md)。本文用有限符号序列解释单模式精确子串匹配，算法示例采用 ASCII，Unicode 另列边界。表格、时序和伪代码均为纸面推演，未执行匹配器、规范化器或性能实验。

## 先约定返回什么，才知道什么叫找到

设文本为 T，长度 n；模式为 P，长度 m。本文索引从 0 开始，区间 `[s,s+m)` 包含 s、不含右端；命中要求对应 m 个单位逐一相等。找第一次出现、列出所有出现、只判断存在，以及非重叠替换，是不同接口。本文列出全部出现并保留重叠：在 `aaaaa` 中找 `aaa`，答案应为 0、1、2。

本篇伪代码要求 m≥1；空模式明确作为不支持的输入，不进入扫描。其他 API 可以约定空模式命中起点或每个边界，但需要单独处理，不能让 `P[0]` 越界。若 m>n，非空模式没有命中；无命中与在位置 0 命中也必须使用不同结果表示。

分析时假定索引、单个符号相等比较和报告一个位置的成本有界。若比较的是变长字素簇，或为了访问第 i 个字符要从头解码，就不能照抄这个成本模型。返回全部 k 个位置至少要处理这些输出；若复制每个命中的完整子串，还要计入复制字节。

## 朴素扫描的重复发生在哪里

直接方法从每个可行起点比较 P，遇到失配就把起点加一。若 m≤n，共有 `n−m+1` 个起点，每个至多比较 m 个符号，故上界为 `O((n−m+1)m)`，常写成 O(nm)。这不是说每次输入都会达到上界。

纸面反例让 T 由许多 a 组成，P 为若干 a 后接 b；每个起点都可先比较很长的 a，最后才失败。接近全部匹配的信息被丢掉，下一个起点又重做。固定短模式可能足够好用，但“代码短”不能证明长模式、重复文本下仍是线性时间。

## 前缀函数保存可以继续利用的相等关系

对模式前缀 `P[0..i]`，定义 π[i] 为其最长真前缀、同时也是后缀的长度。“真”排除整个前缀本身，允许长度 0。表里存长度，不存下一段文本的位置，也不是“失配后总共跳几格”的统一数值。

教学模式为 `ababaca`，完整表如下，可逐格比较左右两端：

| i | P[i] | 截止 i 的前缀 | 最长真前后缀 | π[i] |
| --- | --- | --- | --- | --- |
| 0 | a | a | 空 | 0 |
| 1 | b | ab | 空 | 0 |
| 2 | a | aba | a | 1 |
| 3 | b | abab | ab | 2 |
| 4 | a | ababa | aba | 3 |
| 5 | c | ababac | 空 | 0 |
| 6 | a | ababaca | a | 1 |

若已经匹配 P 的前 j 个符号，下一个符号却失配，新的候选仍须是“已匹配部分的后缀”和“模式的前缀”。先保留最长者，长度为 `π[j−1]`；它若也失败，再沿它的真前后缀回退。随意选一个更短值可能跳过还没排除的候选，回到 j 本身则不会推进。

这个机制可参照 [Jayadev Misra 的 KMP 讲义](https://www.cs.utexas.edu/~misra/Notes.dir/KMP.pdf)中最长真前后缀、候选移动和预处理的推导。讲义按前缀长度保存 core；本篇把它改写成按末尾下标保存的 π，二者下标不能直接混用。

以下是基于上述定义的教学伪代码，不属于已经执行的实现；先检查模式非空：

```text
pi = 长度 m 的全零表
for i = 1 .. m-1:
    j = pi[i-1]
    while j > 0 and P[i] != P[j]:
        j = pi[j-1]
    if P[i] == P[j]: j = j + 1
    pi[i] = j
```

计算 `ababac` 的最后一格时，从 j=3 开始：c 与 P[3]=b 不同，退到 π[2]=1；仍与 P[1]=b 不同，再退到 π[0]=0；c 与 P[0]=a 仍不同，得到 π[5]=0。每次回退都严格缩短候选长度，不会无限循环。

## KMP 回退模式状态，不倒回已经扫描的文本

扫描时用 j 保存当前已经匹配的模式前缀长度，i 向文本右侧推进。报告完整命中后，也用最长真前后缀继续，以保留重叠候选：

```text
j = 0
for i = 0 .. n-1:
    while j > 0 and T[i] != P[j]:
        j = pi[j-1]
    if T[i] == P[j]: j = j + 1
    if j == m:
        emit(i-m+1)
        j = pi[m-1]
```

以 T=`abababacaba`、P=`ababaca` 为例，i=0..4 后 j=5：

| 正在处理的位置 | 比较和状态变化 | 已经确认什么 |
| --- | --- | --- |
| i=5，T[i]=b | 与 P[5]=c 失配，j 从 5 退到 π[4]=3；再与 P[3]=b 匹配，j=4 | 保留此前末尾 aba，不重读 T[2..4] |
| i=6，T[i]=a | 与 P[4]=a 匹配，j=5 | 连续匹配继续增长 |
| i=7，T[i]=c | 与 P[5]=c 匹配，j=6 | 等待最后一个 a |
| i=8，T[i]=a | j=7，报告 `8−7+1=2`，随后 j=π[6]=1 | 命中覆盖 `[2,9)`；末尾 a 可作为后续开头 |

“文本不回退”不等于某个 T[i] 只比较一次：同一符号可能沿多条失败链接比较。线性结论来自整段操作的计数。扫描中 j 每处理一个文本符号至多增加一次，所有回退都严格减少 j；j 不会变成负数，因此总回退数受此前增加量约束，总扫描工作为 O(n)。

前缀表构造也按同样的增加/回退方式计数，耗时 O(m)，表空间 O(m)。在本篇符号模型下，加上 k 个位置的输出，合计 O(n+m+k)；若全部保存答案，另需 O(k) 输出空间。不能只看有两层循环就断定 O(nm)，也不能忽略输入转换与结果输出。

这是前缀函数形式的分析。教材作者的 [algs4 KMP 源码](https://raw.githubusercontent.com/kevin-wayne/algs4/master/src/main/java/edu/princeton/cs/algs4/KMP.java)采用完整 DFA 转移表，明确给出 O(n+mR) 时间和 O(mR) 空间，R 为字母表大小；不能把不同表示的预处理成本混为一谈。本文没有照搬或运行该 Java 实现。

## 安全回退还需要说明不漏报与不误报

可以在处理下一个文本符号前检查这样一个不变量：j 是已读文本后缀中，仍可继续扩展、长度小于 m 的最长模式前缀长度；已形成的完整命中都已经报告。完整命中后立即回退真前后缀，正是为了恢复这个可继续处理下一符号的状态。

不误报来自逐步建立的相等关系：只有 j 达到 m，才有相应 m 个单位与模式全部相等。不漏报则依赖候选的枚举：失配后仍可能成为开头的部分，必须同时是已匹配段的后缀与模式前缀；失败链接按长度逐次检查这些可能性，而非凭经验跳过几个字符。这和“实测样例没有漏”是不同层次的证据。

尤其不能在回退到 j=0 后直接丢弃当前文本符号。本例伪代码会继续拿它与 P[0] 比较。纸面设 T=`aab`、P=`ab`：读到第二个 a 时先与 b 失配，回到 0 后，这个 a 自己又是新起点；接着 b 应在位置 1 形成命中。若把失配符号无条件吞掉，就会漏掉这一处。

这些不变量也帮助发现边界错误：j 存长度，所以读取“下一个待比模式符号”用 P[j]；已经匹配的末尾下标却是 j−1，所以回退查 π[j−1]。报告后若保留 j=m，下一次再读 P[j] 就越过模式。把任意失败表当成可互换[数组](../../glossary/algorithms.md#algorithms.sequences)，会同时破坏数组边界和候选完整性，即使某个单一模式看起来仍能工作。

## 重叠和读取块都要延续同一个状态

在 `aaaaa` 中找 `aaa`，π 为 `[0,1,2]`。首次在 i=2 命中后把 j 置为 2，随后 i=3、4 各补一个 a，分别报告 1、2。若每次命中都清零 j，会漏掉本篇契约要求的重叠；若产品只允许非重叠结果，则应另行约定推进规则。

将前例文本拆成 `ababa | bacaba`，两块各自都短于 7，单独查找没有结果。跨块处理保留模式、π、j 与全局已消费单位数：第一块后 j=5，第二块继续前述回退，仍报告全局位置 2。j 表达当前前后缀相等关系，因此无需保留全部历史文本来重新扫描；如果要返回原文片段而非位置，就还需相应缓冲或可回读来源。

这份状态只对同一模式和相同比较规则有效。读取过程中换模式，或改变编码单位、规范化版本，却继续使用旧 π、j 和全局偏移，会破坏相等关系。若处理需要断点恢复，应连同输入位置保存匹配配置及必要转换状态，并另定已经报告结果的重复处理规则，不能只记录“读到了第几个块”。

这只处理已经变成匹配单位的序列。字节流可能在一个 UTF-8 编码序列中间截断，增量解码需保留未完成字节并按契约处理非法或截断输入。不得先把每块独立解码、替换坏字节，再声称与整份文本的精确匹配等价。

## Unicode 中，位置单位与相等规则分别决定答案

按 [Unicode 17.0.0 §3.9](https://www.unicode.org/versions/Unicode17.0.0/core-spec/chapter-3/)的编码定义，一个标量可占一个或多个码元。合法文本 `A😀B` 中，😀 是 U+1F600；B 的起点有如下不同计数，均从 0 起：

| 计数单位 | B 之前的单位数，即起点 |
| --- | --- |
| UTF-8 字节 | 1+4=5 |
| Unicode 码点 | 1+1=2 |
| UTF-16 码元 | 1+2=3 |
| 本例默认扩展字素簇 | 1+1=2 |

字素簇用于近似表达用户感知的字符，但不等于码点数或显示宽度；其默认边界及组合字符规则见 [UAX #29，Unicode 17.0.0，rev47](https://www.unicode.org/reports/tr29/tr29-47.html)。[KMP](../../glossary/algorithms.md#algorithms.string-matching) 在某种单位上比较正确，不表示返回值可直接用作另一种字符串 API 的下标。按码元匹配时，还要决定是否允许在代理项对或用户感知字符内部截断。

原样码点比较下，预组合 é 与 `e + U+0301` 是不同序列。若业务要求规范等价，可在明确规则下将模式与文本规范化；[UAX #15 rev57](https://www.unicode.org/reports/tr15/tr15-57.html)区分 NFC/NFD 与兼容规范化，不能未经约定就抹掉身份或文本意义上的区别。

转换还会改变长度与位置。[Unicode 17.0.0 CaseFolding.txt](https://www.unicode.org/Public/17.0.0/ucd/CaseFolding.txt)中的完整折叠可将 ß 变成 ss，它不同于简单把每个字母变小写；折叠也不自动保持规范化。要高亮原文或返回原始偏移，需维护转换后范围到原始范围的映射，不能把命中长度直接当成原文字符数。

流式处理还要保留转换边界。单独对 `e | U+0301` 两块做 NFC 再拼接，仍可能得到两个码点；整体 NFC 可组合成 é。UAX #15 §1.4 明确规范化形式不对拼接封闭。支持跨块输入的匹配状态，不会自动补齐增量解码、规范化或字素分段所需的上下文。

## 哈希、字典索引与正则回答不同问题

滚动哈希可快速更新相邻窗口的摘要；摘要不同可排除，摘要相同却仍可能[碰撞](../../glossary/algorithms.md#algorithms.hash-table)。需要精确答案时应对候选核对原文，教材作者的 [RabinKarp 源码](https://raw.githubusercontent.com/kevin-wayne/algs4/master/src/main/java/edu/princeton/cs/algs4/RabinKarp.java)就在哈希命中后调用字符检查。保留核对可保证这个相等判定，却还需把候选核对成本纳入时间分析；不能把哈希阳性直接当作精确匹配或密码学完整性证明，相关区别见[哈希与键契约](hash-tables-collisions-and-key-contracts.md)。

[Trie](tries-prefix-search-and-key-encoding.md)组织一组键及共同前缀，不会仅凭建树就完成长文本中的任意位置多模式扫描；需要另行设计状态转移、失败处理和输出。[倒排索引](../../glossary/cache-search.md#cache-search.inverted)查的是按[分析规则](../cache-search/inverted-indexes-analysis-and-relevance.md)保存的词项与位置，也不等于原始字节子串匹配。正则表达式又引入自己的语法、匹配策略及引擎能力，不能给所有 regex 或语言自带 substring 函数套上本文 KMP 的复杂度。

本篇未提供可运行实现。后续验证可在相同单位与空模式契约下，用朴素方法对照小输入全部结果，加入重叠、重复前缀、m>n、各切块位置和 Unicode 转换映射；这属于待执行计划，方法见[属性测试与状态模型](../engineering/property-testing-and-state-models.md)，不是已经通过的测试。
