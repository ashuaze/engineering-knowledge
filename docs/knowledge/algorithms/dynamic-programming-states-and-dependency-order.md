# 动态规划与状态设计：记住子问题，为什么还会算错

学习入口：已经加了缓存、填了 dp [数组](../../glossary/algorithms.md#algorithms.sequences)，为什么结果仍重复使用同一物品，或把不可能的方案算成可行？前置：[复杂度](complexity-and-data-structures.md)、[图与依赖顺序](graphs-traversal-and-dependency-order.md)。本文讨论有限输入下的状态递推；表格、公式和伪代码为教学设计，没有执行求解器或基准。

## 先定义一个状态究竟代表什么

[动态规划](../../glossary/algorithms.md#algorithms.dynamic-programming)把原问题分解为可复用子问题，保存结果，避免对同一状态反复求解。关键不是数组名字，而是哪些历史可以归为同一状态，以及这些历史是否具有相同的后续可选行动和成本规则。状态漏掉影响未来的约束，缓存只会更快复用错误答案。

例如“剩余容量相同”不一定足够：已经用掉哪些物品、是否还可用折扣、是否必须连续选择，都可能改变未来。需要的状态字段由问题契约决定；把全部历史都保存又可能产生指数级状态，不能只靠记忆化承诺高效。

一种设计顺序是：用自然语言定义状态，列出完整且不重不漏的选择，写基本情况，证明依赖能按某种顺序求解，最后说明原答案如何取出。记忆化与表格法、子问题图和成本分析参照 [MIT 动态规划框架](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_lec15/)。

## 0/1 背包把物品范围也放进状态

本例有 n 件物品，每件最多取一次；重量为正整数、价值为非负整数，容量 C 为非负整数，允许留空且不要求恰好装满。要在总重量不超过 C 的前提下最大化总价值。D[i,c] 定义为“只使用前 i 件、容量上限为 c 时的最大价值”，物品编号为 1 到 n。

若第 i 件重量为 wᵢ、价值为 vᵢ：

```text
D[0,c] = 0；D[i,0] = 0
若 c < wᵢ：D[i,c] = D[i−1,c]
否则：D[i,c] = max(D[i−1,c], D[i−1,c−wᵢ] + vᵢ)
原问题答案 = D[n,C]
```

任一可行方案只有不取或取第 i 件两种情况；取时，剩余方案只能用前 i−1 件，容量上限缩小。因此两种候选覆盖所有方案，且子问题最优解组合仍满足约束；按 i 递增，可由前一行建立当前行的正确性。这比先猜一段双层循环更容易核对。模型与递推参照 [MIT 0/1 背包材料](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_r18/)。

纸面物品 A=(重量 2,价值 3)、B=(3,4)、C=(4,5)，容量 5：

| 可使用的物品 | 容量 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| 无 | 0 | 0 | 0 | 0 | 0 | 0 |
| A | 0 | 0 | 3 | 3 | 3 | 3 |
| A、B | 0 | 0 | 3 | 4 | 4 | 7 |
| A、B、C | 0 | 0 | 3 | 4 | 5 | 7 |

答案是 7，对应 A+B，不是选价值最高的 C，也不是把 A 多取几次。这里列出了本例全部容量状态，表格不是工具运行输出。

若要求恰好装满，状态改为“前 i 件中总重量恰为 c 的最大价值”：D[0,0]=0、D[0,c>0]=−∞，正重量前提下 D[i,0]=0；转移时跳过不可达来源。不能把不可达容量全部填 0，应区分“容量可行但价值为零”与“根本无法达到”，并防止哨兵被当作普通结果。修改可行性契约，就要重查初始化、转移及最终取值。

## 求值顺序来自依赖，压缩空间不能改掉语义

自顶向下的记忆化按需要访问状态，自底向上的表格法按依赖顺序计算；在相同状态定义和转移下，可以计算相同答案。前者可能避开无需求状态，也需递归栈；后者常按规则扫描整表。记忆化不自动解决[循环依赖](../../glossary/runtime.md#runtime.modules)；若状态相互等待，需要找出终止量、增加阶段或使用适合该问题的收敛方法。

上述二维式只依赖前一行，可用一维数组压缩。下面是说明性伪代码，不是已运行实现：

```text
dp[0..C] 全部置 0
逐件处理 (w,v)：
    c 从 C 递减到 w：
        dp[c] = max(dp[c], dp[c−w] + v)
```

递减时 c−w<c，其位置在本轮尚未更新，读到的是前一行的值。若递增，在仅处理 A 时就会先令 dp[2]=3，再令 dp[4]=dp[2]+3=6，把同一件 A 算两次；二维表该位置应为 3。递增可用于某些允许重复取用的背包转移，但那是另一份契约，不能作为 0/1 版本的小改动。依赖方向与重复物品的差异也见上述 MIT 背包材料。

求最优值和恢复选择是不同输出。完整表可从 D[n,C] 比较取/不取来源逐项回溯，若并列需约定选择；只留一行后，不能假定当前数组仍含所有历史阶段的来源。需要额外的决策记录或重算方案，不能靠指向不断被覆盖的槽位保证正确恢复，也不自动枚举全部最优方案。

## 状态数乘每态工作量仍有数值口径

完整表有 (n+1)(C+1) 个状态，每态做有界次数的比较和加法；通常对正 n、C 简写为 O(nC) 时间，完整表空间 O((n+1)(C+1))，压缩后的值数组为 O(C+1)。这里按有界机器字或表项计空间，输入和方案输出另计；本例记忆化递归深度还可达 O(n)。若数值超出机器字范围，每项位数和算术成本也需展开。

C 是容量数值，不是它的二进制编码长度。容量约 2ᵇ 时，容量维就可接近 2ᵇ，而编码容量只需量级 b 位；所以这个方法是伪多项式算法，不能只看到两层循环就称其对输入位数为多项式。相关区分见 [MIT 伪多项式讲义](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/resources/mit6_006s20_lec18_pdf/)。状态中包含任意子集时也可能有 2ⁿ 种，动态规划并不消除所有组合爆炸。

尚未复用子问题时的选择树、状态撤销和安全剪枝，继续见[分治与回溯](divide-and-conquer-backtracking-and-pruning.md)。存在性可复用的状态不一定允许枚举时跳过不同前缀，输出全部方案仍需计入组合与保存成本。

## 递推正确性与实现对照分别验收

先证明每个合法方案都被某个转移覆盖，转移不生成非法方案，并且按依赖顺序计算能得到状态的含义。再设计空输入、零容量、单物品、重复重量、并列价值、恰好/不足容量和一维方向的实现检查。小实例穷举所有子集可作为后续正确性对照，不能仅拿期望答案来自同一递推的第二份实现互证。

[贪心](greedy-choices-and-exchange-arguments.md)需要额外证明一条局部选择足够；动态规划则保存多个不同状态的最好结果。[最短路](weighted-shortest-paths-and-relaxation.md)中的分层边数或 [DAG](../../glossary/algorithms.md#algorithms.graph-traversal) 顺序也体现状态依赖；这些联系不表示任意有环递推都能靠普通 memo 自动完成。

自检：两个状态相同是否真的意味着未来相同？初始化是“至多”还是“恰好”？依赖严格向哪个维度推进？压缩后读到的是上一阶段还是本轮新值？要最优数值还是实际方案？复杂度的规模是编码长度还是数值？
