# 分治与回溯：怎样拆开问题，又怎样安全地排除分支

学习入口：代码都在递归调用自己，为什么一种只需对数层，另一种却要探索指数多个分支？已经找到一个可行方案，为什么不能立刻宣布最优？先定义每次调用要回答的问题，再核对哪些子问题必须全部解决、哪些候选可以有证明地排除。

前置：[复杂度与结构选择](complexity-and-data-structures.md)、[排序与二分边界](sorting-binary-search-and-boundaries.md)。本文讨论有限输入、确定目标下的递归分解与组合搜索。算术和状态访问按有界成本模型分析，实际数值位数、语言栈限制与数据复制另计。树、数字和伪代码均为纸面教学设计，未执行算法、求解器或性能实验。

## 递归是组织方式，问题契约决定怎样使用它

递归调用需要基本情况，并沿可证明终止的方向推进。例如以非负整数规模衡量时，每次调用严格缩小规模，最终应到达能直接处理的情况。只写 `if n == 1` 不够：空输入是否可能到达、划分是否产生不变规模、状态是否会绕回，都要检查。原理参照 [Jeff Erickson《Algorithms》Recursion §1.2](https://jeffe.cs.illinois.edu/teaching/algorithms/book/01-recursion.pdf)。

| 机制 | 一次调用回答什么 | 分支之间怎样合成 |
| --- | --- | --- |
| [分治](../../glossary/algorithms.md#algorithms.divide-conquer) | 原问题怎样拆成同类的更小问题 | 通常需要取得所需子问题结果，并用正确的合并步骤构造原答案 |
| 回溯 | 当前部分选择有哪些合法的后续完成 | 尝试候选、返回并恢复选择；可以找存在性、一个解、全部解或最优解 |
| [动态规划](../../glossary/algorithms.md#algorithms.dynamic-programming) | 哪些历史具有等价的后续问题 | 用充分状态复用结果，避免相同子问题反复求值 |
| 贪心 | 能否证明这次局部选择无需撤回 | 只有安全选择论证成立，才可承诺一条选择而不探索其他候选 |

这些关系不是四种互斥语法。[回溯搜索](../../glossary/algorithms.md#algorithms.backtracking)可用[深度优先](../../glossary/algorithms.md#algorithms.graph-traversal)遍历实现，递归式也可能经过状态复用转为动态规划；换成循环或显式栈，不会自动改变所需探索的问题集合。相关区别见[图遍历](graphs-traversal-and-dependency-order.md)、[动态规划](dynamic-programming-states-and-dependency-order.md)和[贪心与交换论证](greedy-choices-and-exchange-arguments.md)。

## 分治要证明子问题足够，合并也正确

以归并[排序](../../glossary/algorithms.md#algorithms.sorting-search)为例，调用契约是“输出这个区间的有序排列，保留全部元素和重复次数”。把区间分为两半，各自正确排序后，用合并步骤取得整体有序结果；如果合并漏掉重复项，即使两次递归都正确，整体仍错。大小为零或一的区间可直接返回；半开区间的中点与长度必须确保两个子区间严格缩小。

证明可分为三层：基本情况正确；假设更小子问题满足契约；说明分解和合并把这些结果变回原问题的合法答案。这是归纳论证，不是“样例排对了”。[MIT 6.006 Spring 2020 Lecture 3](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/6d1ae5278d02bbecb5c4428928b24194_MIT6_006S20_lec3.pdf)分别分析合并的正确性与成本、整个归并排序的递推。

按输入切成两块，也不保证两块能各自独立求最优再拼接。例如两组任务共用一台设备，两边分别得到的可行排程仍可能互相冲突；必须把跨块约束纳入子问题接口或合并过程。子问题的规模更小、局部答案正确，只完成了论证的一部分。

一份常见分析式是 `T(n)=2T(n/2)+Θ(n)`：两项递归成本之外，还要计入分解、合并和必要复制。这里只是规模为二的幂时的平衡模型；一般区间应处理上下取整及基本情况，不能把形式直接套给任意递归。

## 层数只描述深度，总成本要把同层分支相加

纸面计费模型：n=8，每个内部结点的本地工作计为其区间长度，每个单元素叶结点计 1 单位；这不是实际比较次数或耗时。

| 深度 | 子问题数 | 每个规模 | 这一层计费 |
| --- | --- | --- | --- |
| 0 | 1 | 8 | 8 |
| 1 | 2 | 4 | 2×4=8 |
| 2 | 4 | 2 | 4×2=8 |
| 3 | 8 | 1，基本情况 | 8×1=8 |

从根到叶有 3 条边，但共有 4 层计费，总计 `8+8+8+8=32`。对 `n=2^k`，内部有 k 层，每层 n，加上 n 个叶，得到 `n·log₂n+n`；这套模型的总成本是 Θ(n log n)，不是 Θ(log n)。归并实际比较次数可能小于这项计费，不能把 32 当作执行结果。

二分定位只继续一个半区间且本地工作有界，才有 `T(n)=T(n/2)+Θ(1)` 的对数成本。若每次只去掉一个元素，本地又扫描剩余区间，则 `T(n)=T(n−1)+Θ(n)` 累加为 Θ(n²)，递归深度也可线性增长。[Erickson Recursion §1.5](https://jeffe.cs.illinois.edu/teaching/algorithms/book/01-recursion.pdf)用快速排序说明划分平衡与极端失衡的差别；“用了分治”不保证每次都分得均匀，更不意味着实际自动[并行](../../glossary/systems.md#systems.concurrency)。

## 回溯先固定状态，再保证选择能撤销

下面另设问题：输入[数组](../../glossary/algorithms.md#algorithms.sequences) `a=[2,3,5]`，每个位置最多选择一次，枚举元素和为 5 的全部位置子集。状态为“下一个待决定位置 i、当前和 s、已选位置 path”；同值不同位置在本契约中仍是不同选择。

未加剪枝的完整搜索树如下，左边取当前元素，右边不取；叶上的数是该位置子集的和：

```text
                         s=0
                  取2 /       \ 不取2
                    2           0
              取3 / \不取3  取3/ \不取3
                 5    2        3    0
          取5/ \不取5 /\      /\    /\
            10  5    7  2    8  3  5  0
```

八个叶依次对应 `{2,3,5}`、`{2,3}`、`{2,5}`、`{2}`、`{3,5}`、`{3}`、`{5}`、空集。两个解是位置 `{0,1}` 与 `{2}`；完整二叉决策树有 `1+2+4+8=15` 个结点。这里完整列树只为核对覆盖，未运行程序。

[Stanford CS106B，2020-04-29](https://web.stanford.edu/class/archive/cs/cs106b/cs106b.1206/lectures/backtracking1/)把常见过程组织为 choose、explore、unchoose，即选择、探索、撤销。下面是本例的说明性伪代码，使用共享可变 path，尚未执行。本例 n 为数组长度 3，target=5，path 初始为空，从 search(0,0) 开始：

```text
search(i, s):
    如果 i == n:
        如果 s == target: 输出 path 的副本
        返回
    path 末尾加入 i
    search(i+1, s+a[i])
    撤销 path 末尾的 i
    search(i+1, s)
```

进入 `search(i,s)` 时，path 只记录位置 0 到 i−1 的选择，s 等于这些值的和；返回时必须恢复调用者原有的 path。否则“不取”分支会继承“取”的历史。若保存同一个可变列表引用而不复制，后续撤销也可能改掉已经输出的答案。值语义、持久结构或显式状态副本可以采用其他恢复方式，但应说明其复制成本。

若具体实现允许异常或取消退出，恢复责任也不能只安排在正常返回后；要保护共享状态的退出路径。这里的撤销只针对搜索过程里的受控内存修改，不表示发送邮件或支付等外部动作可以随[调用栈](../../glossary/systems.md#systems.memory-layout)返回自动逆转。

正确性要同时看可靠性与完整性：每个输出都满足一次选取与目标约束；每个合法位置子集又恰好对应一条取/不取路径。去重若改成按数值集合处理，会改变同值不同位置的语义，必须另定规范化和去重规则。基本情况、候选划分和状态恢复的意义也见 [Erickson Backtracking §2.1–§2.4](https://jeffe.cs.illinois.edu/teaching/algorithms/book/02-backtracking.pdf)。

## 剪枝需要证明余下分支不可能提供所需答案

可行性剪枝排除“没有合法完成”的部分状态。若所有未处理元素非负，当前和已经大于目标，就不可能再靠后续选择减回目标；这时可停止该分支。前提改为允许负数后，这条理由失效：`a=[5,-2]`、目标 3，取 5 后若因 `5>3` 剪掉，便漏掉合法解 `5+(-2)=3`。Erickson 的相应 Subset Sum 章节限定正整数，不能忽略该条件照搬到任意整数。

即使没有负数，枚举全部解也不能把“已达到目标”统一当作终点。例如 `[3,0]`、目标 3，有位置子集 `{0}` 和 `{0,1}` 两个解；取 3 就停止会漏掉第二个。本例伪代码直到 i=n 才输出，正是为了保留完整后续选择。只问是否存在一个解时，则可以在已经获得符合契约的解后提早返回。

对允许负数的有限数组，可以在纸面上定义后缀下界 `lo[i]=Σmin(a[j],0)`、上界 `hi[i]=Σmax(a[j],0)`，求和范围为 j≥i。任何后续子集和都在 `[lo[i],hi[i]]` 内，因此目标不在 `[s+lo[i],s+hi[i]]` 时可安全剪枝。这个区间可能很松：剩余 `[4,6]` 时区间为 `[0,10]`，包含 5，却没有子集能凑成 5；落在界内不能当作已经可行。这里的边界是对所有可能完成的保守包围，不是一次猜测。

最优性剪枝回答另一种问题。最小化时，已有完整可行解的成本 U 是当前上界；某分支的 L 若不大于它的任何合法完成成本，才是有效下界。如果 L≥U，该分支不能严格改进当前最好值；求一个最优解时可据此剪去。若要枚举全部并列最优解，L=U 的分支仍可能含新答案，不能同样丢掉。最大化问题的方向需要对应反转。

上下界必须可证明；把部分方案的费用直接当下界，也要先排除后续负费用等可能。一个“看起来很难更好”的估值只是启发式。依据见 [Stanford EE364b Branch and Bound](https://web.stanford.edu/class/ee364b/lectures/bb_slides.pdf)对可证明上下界和全局结果证书的解释；本文只取界的基本逻辑，不展开连续优化求解器。提前到达时间或结点预算，仅说明搜索未完成，除非仍有覆盖全部未探索分支的证据，否则不能宣布不存在解或已经最优。

优先探索更有希望的候选，可能更早取得较好的 U，从而让有效界排掉更多分支；这改变搜索次序，不自动改变最坏规模。没有排除证明的分支仍需保留，不能因为前几个候选表现较差就全部忽略。若采用截止深度或估值代替完整探索，应把返回结果的保证相应降低。

## 搜索树、复用状态与输出空间分别计费

无剪枝的 n 次二选一有 2ⁿ 个叶，整棵树有 `2^(n+1)−1` 个结点；逐层 DFS 只同时保留一条路径，但总工作仍可能指数增长。按每结点有界判断、增删状态计费，探索本身为 O(2ⁿ)；若输出 R 份答案、总共复制 B 个位置，还要加上 O(B+R) 输出工作。枚举全部子集时，对正 n，总位置条目为 `n·2^(n−1)`，输出本身就可达 Θ(n2ⁿ)。

上述按路径增删的实现，辅助栈和路径为 O(n+1)，并不是把所有树结点都同时存住；保存全部答案则另需 O(B+R) 空间。若每次递归复制整份历史、重新计算后缀界，或者数值超过有界机器字，就要把这些工作展开。分治的栈深度也不等于全部辅助空间：合并缓冲、切片和返回值可能占据更大内存。

改用[显式栈](sequences-stacks-queues-and-deques.md)时，帧还需保存当前候选位置、返回后要继续哪一步及待撤销的选择；仅把递归函数名换成一个栈容器，不会自动保存这些控制信息。先画正常进入和返回，再决定状态是复制还是共享。

把存在性问题的 `(i,s)` 作为充分状态时，不同路径可复用同一个后续判断，这连接到动态规划；但若枚举不同前缀的全部方案，仅用全局 visited 跳过重复 `(i,s)` 会漏掉答案。可以复用后缀结果再与各前缀组合，输出与存储仍有成本；不能把“加了记忆化”直接等同多项式时间。

例如 `[1,1,1]`、目标 2，在处理完前两个位置后，前缀 `{0}` 和 `{1}` 都到达 `(i=2,s=1)`。两者再取位置 2 分别得到 `{0,2}` 和 `{1,2}`；仅因状态相同跳过后一个，就丢掉本契约要求的一个方案。

实现验证应分别覆盖空输入、单项、零、负数、重复值、多个解、无解、界相等、共享状态撤销和极深调用。小输入的完整枚举可作为后续剪枝实现的独立对照，检查策略见[属性测试与状态模型](../engineering/property-testing-and-state-models.md)；模型正确性、实际实现通过和性能改善是三种证据，不能互相替代。
