# 贪心选择与交换论证：每一步最好，为什么未必整体最优

学习入口：调度时优先选最早开始、最短任务或最高收益，哪一种一定正确？前置：[排序契约](sorting-binary-search-and-boundaries.md)、[复杂度](complexity-and-data-structures.md)。本文讨论有限、全部输入预先可见的离线优化问题；以单资源区间选择为主例，规则、反例与推导均未作为调度实验执行。

## 局部规则必须对应明确目标

[贪心算法](../../glossary/algorithms.md#algorithms.greedy)按一个规则逐步做出选择，并在该算法中不撤回已承诺的选择。“最好”必须先定义：选中数量最多、总收益最大、[延迟](../../glossary/performance.md#performance.latency-throughput)最小和机器数最少是不同目标。每次选择都合法，只证明可行；最终没有位置再加任务，只证明不能直接扩充，都不等于全局最优。

本文问题固定为：每个任务占用一个预先给定的半开区间 [s,f)，且 s<f；使用同一资源，互不重叠，目标是选中任务数最多，每个任务贡献相同的 1。前一个结束时刻等于后一个开始时刻允许衔接；没有切换时间、优先级、依赖或机器差异。问题与证明依据见 [MIT 区间调度讲义](https://ocw.mit.edu/courses/6-046j-design-and-analysis-of-algorithms-spring-2015/ff2a7015ff913fc01f0381d8f5126a9a_MIT6_046JS15_lec01.pdf)。

## 最早结束给剩余任务保留空间

规则是按结束时刻升序扫描，若当前任务的开始不早于已选最后任务的结束，就接纳；空集合允许接纳第一个。结束相同可用稳定 ID 决定顺序，便于复现，但最优集合本来就可能不唯一。

纸面输入只有下列五项：

| 任务 | 区间 |
| --- | --- |
| A | [0,6) |
| B | [1,3) |
| C | [3,5) |
| D | [5,7) |
| E | [7,8) |

最早结束顺序为 B、C、A、D、E。选择 B、C，跳过与已选任务冲突的 A，再选 D、E，得到 4 项。最早开始会先选 A，之后只能选 E，得到 2 项；这个集合已经不能再直接加入其余任何任务，却仍不是最优。

不能据这一个成功例子证明规则总成立。下面的论证要覆盖全部符合前提的输入，包括并列结束和相接边界。

## 交换论证解释为什么这次选择安全

取任意一个最优解，按时间顺序排列。设其中第一项为 o，全部候选中最早结束的项为 g。因为 f(g)≤f(o)，把 o 换成 g，不会挤掉该解中位于 o 后面的其他任务；个数保持不变，仍可行。因此，至少存在一个最优解以 g 开头，而不是声称所有最优解都必须包含 g。

接着只考虑开始时刻不早于 f(g) 的剩余任务，得到同一种更小问题。若后续没有选到最多个数，就可以换成更好的后续，使原解也改进，与最优性矛盾。反复应用这个安全选择，配合空输入等基本情况，才得到整体最优。

交换步骤不只是“看起来给后面留得更多”。必须说明拿哪份最优解、交换什么、为什么不破坏约束、为什么目标不变差，以及为什么剩余问题仍满足前提。可分解成最优子问题，也不自动保证某个局部选择安全；[动态规划](dynamic-programming-states-and-dependency-order.md)通常还需比较多个候选分支。

## 反例要针对规则和契约

最短持续时间也没有本题的通用保证。另一个独立纸面输入为 L=[0,3)、M=[3,6)、X=[2,4)。先选持续 2 的 X，会与 L、M 都冲突，只能选 1 项；选 L、M 可得 2 项。最短任务可能跨过两个本可衔接任务的边界。

把目标改成总收益，又需要重新论证。仅有 P=[0,2)、收益 1，Q=[2,4)、收益 1，R=[0,4)、收益 10 时，最早结束选 P、Q，总收益 2；选 R 则为 10。原规则仍能得到本例最多的 2 项，却不再最大化收益。不能把“数量最优”的证明改个标题就用于加权选择。

类似地，自设面额 {1,3,4}、每种可重复、凑金额 6 并最少用币：每次取不超过余额的最大面额会选 4+1+1，共 3 枚；3+3 只需 2 枚。某些面额体系可另行证明贪心，但“总有 1 可以凑出”只保证可行，不保证币数最少。

找到一个反例足以否定某条规则的普遍保证；一批随机输入都没有反例，仍不能代替证明。小规模穷举可作为后续实现对照，须枚举所有合法子集并核对目标，而不是拿另一个未证明的启发式当标准答案。

## 排序成本、输入可见性与工程目标都要保留

比较与区间检查按有界成本计时，[排序](../../glossary/algorithms.md#algorithms.sorting-search)一般需 O(n log n)，已排序后扫描为 O(n)。输出最多 n 项，需要相应保存空间；排序是否原地、是否复制输入，由实现另外说明。不要因为扫描只有一层循环就忽略排序与输出。

离线输入已知，和任务到来时立刻接纳且不可撤回的在线场景不同。原证明中的全局最早结束选择，在不知道未来时未必可用。真实任务还可能提前/[超时](../../glossary/api.md#api.retries)、改变占用区间、需要多份资源；抽象解只优化其模型，不能直接宣称系统吞吐、响应时间或公平性最优。

其他贪心有自己的安全条件：[Dijkstra](weighted-shortest-paths-and-relaxation.md)依赖非负权下的确认规则，[Kruskal](union-find-components-and-minimum-spanning-trees.md)依赖割与无环森林。它们不是因为都使用排序或堆，就共享同一份最优性证明。

自检：目标是个数、收益还是延迟？规则得到的是可行、不能扩充还是最优？能否把某个最优解的第一步换成贪心选择？等价交换后，剩余输入和约束是否仍然相同？
