# 记忆权限、撤销与删除：不可检索为什么不等于彻底清除

学习入口：记忆已删除，为什么旧缓存或备份里还能找到原文？前置：对象[授权](../../glossary/security.md#security.identity)、记忆版本与派生副本。首先说明删除目标：是停止当前使用、清理活动副本，还是处理日志、备份和其他保存位置。一次查询没有返回，只能证明这个查询路径下没有返回。

## 记忆的作用域需要可信身份

[命名空间](../../glossary/devops.md#devops.isolation)可以按租户、主体、项目或任务组织数据，但 namespace 本身不是授权。客户端或模型填写某个用户 ID，不能证明它代表该用户；共享项目记忆也需要明确哪些成员可读、谁能修改。

[OWASP 授权指南](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html#validate-the-permissions-on-every-request)强调默认拒绝及逐请求检查。记忆路径同样需要覆盖检索、缓存命中、来源预览、导出、恢复和管理接口。不能只在建立会话时检查一次，更不能先把越权内容送入模型，再让模型决定是否引用。

教学读取策略先检查当前成员关系，候选再核对租户与对象关系。缓存键包含主体和租户可以减少混用，但缓存中的旧权限不能替代当前授权。来源已进入模型上下文或已发给用户的内容，也不会因为后续撤权而自动收回。

## 撤权、过期和删除作用不同

| 动作 | 主要改变什么 | 不能自动推导什么 |
| --- | --- | --- |
| 撤销某主体访问 | 该主体后续读取许可 | 记录已经删除，其他主体也不能读 |
| 到达用途期限 | 内容是否仍可按当前策略使用 | 所有存储字节已经清理 |
| 逻辑删除 / tombstone | 权威记录不再作为活动内容使用 | 索引、缓存、日志和备份同步消失 |
| 清理派生副本 | 指定索引、缓存等位置的记录被移除 | 底层介质和未知副本已擦除 |
| 备份与历史留存处理 | 历史副本的访问、保留或清理 | 当前数据库一次 DELETE 能改变旧备份 |

设计中应为每一项定义完成依据，而不是统一返回“全部忘记”。这是工程范围说明，不替代组织的数据保留与适用要求。

## 删除后怎样防止旧任务回填

教学时序：任务先捕获 m1/v1 → 用户删除 m1 → 任务完成并尝试发布旧副本。如果只删除索引，没有权威删除标记或版本限制，旧内容可能重新出现。

一种教学策略是保留不含原文的 tombstone，提高版本并使读取失效，发布时拒绝旧版本；清理索引和缓存再分别记录。稳定身份不能随意复用，否则迟到消息可能误作用于新记录。tombstone 本身也有身份元数据和保存成本，其范围与期限需要设计。

若系统允许删除后以新身份重新创建内容，也要防止旧任务、旧授权或旧来源误关联。跨服务投影可能异步完成，读取路径仍需核对当前权威状态；不能只依赖“清理消息已经发送”。

## 派生材料需要一份可追踪清单

记忆可能进入原始记录、摘要、索引片段、向量、查询缓存、模型输入、追踪日志和导出文件。删除时先确定拥有和控制哪些副本，再记录相应处理状态与失败[重试](../../glossary/api.md#api.retries)。审计通常只需必要标识和处理结果，复制完整原文会增加待治理位置。

来源哈希、摘要与向量也不应被自动当作无敏感性的数据。无法从一次活动查询看见，不代表别人无法通过其他访问路径取得。由记忆生成的结论或已发送消息，也不一定能仅靠删除来源自动改正，需要额外的影响分析。

## 备份恢复会带来旧状态

[SQLite Backup API](https://www.sqlite.org/backup.html)可以生成独立数据库副本，本库实验实际保留删除前备份，活动记录清理后仍能从备份读取旧值。这说明活动库删除不会追溯修改已经生成的副本。

恢复旧备份时应先隔离访问，再根据系统设计恢复当前授权和删除记录，核对是否可能重新暴露旧内容。删除账本如果也只存在于同一份旧备份中，就不能凭恢复成功声称当前删除意图已保留；这里的重新应用流程尚未实现。

数据库删除行与底层安全擦除也不同。[SQLite secure_delete 说明](https://www.sqlite.org/pragma.html#pragma_secure_delete)讨论了数据库内容清理的特定范围及限制。本文不提供跨日志、文件系统、存储介质和第三方副本的完全擦除承诺。

## 怎样验证，而不是只看返回文本

至少对照：先暖缓存再撤权、为另一个租户构造相同查询并注入外租户缓存候选、删除后读旧索引、让旧发布任务迟到、重开数据库后再次查询、清理活动副本后读取旧备份。权威状态不可用时，要明确报不可用或按预设策略停止，不能悄悄用未经确认的旧缓存满足严格授权请求。

[记忆治理实验](memory-governance-lab.md)提供这些局部对照。它使用可信身份夹具、[逻辑时钟](../../glossary/distributed.md#distributed.clocks)与可控制时序，验证当前查询输出和数据库记录；没有真实身份平台、向量引擎、[并发](../../glossary/systems.md#systems.concurrency)权限修改、线上备份治理或介质擦除。
