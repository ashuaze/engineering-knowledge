# 记忆写入与来源：哪些内容值得成为长期记录

学习入口：模型把“用户可能偏好英文”写进[长期记忆](../../glossary/ai.md#ai.memory)，下一次就能当成用户确认过的偏好吗？前置：上下文、持久化与工具结果。保存一段内容只改变了它的存储位置，不会提升它的事实性或[授权](../../glossary/security.md#security.identity)级别。记忆需要能回答：谁说的、依据是什么、适用谁、有效到何时，以及为什么值得保存。

## 先区分用途，再选择记忆表示

| 内容 | 合适的定位 | 不自动成为 |
| --- | --- | --- |
| 当前会话的临时条件 | 本任务上下文或状态 | 跨任务长期偏好 |
| 用户明确表达的偏好 | 有作用域和来源的用户陈述 | 对其他用户或所有场景的规则 |
| 对过去过程的记录 | 可回查的情境经历 | 下一次行动必然适用的策略 |
| 模型从行为推测的偏好 | 待核实假设 | 已确认事实或可信用户指令 |
| 工具返回的业务结果 | 按工具契约核实的观察 | 模型摘要能够替代的权威业务状态 |

[LangChain 的 Memory overview](https://docs.langchain.com/oss/python/concepts/memory)区分会话范围与跨会话记忆，并借用 semantic、episodic、procedural 等名称组织事实、经历和规则。这是理解用途的一种框架，不是所有产品通用的存储标准。把一次成功操作总结成经验，也不代表它适用于当前权限、版本与对象。

用户说“我喜欢中文”，可以支持“该用户在这次表达中偏好中文”；用户说“我是管理员”，不能因此建立管理员权限。来源可信也不表示它对所有问题都有权威性，需要同时限定声明类型。

## 写入是一项受控动作

教学写入链路可以组织为：

```text
候选内容 → 确定用途与主体范围 → 查来源及支持关系
         → 校验写入权限与必要确认 → 选择新建、更新或保留冲突
         → 保存版本和生命周期 → 更新派生检索材料
```

并非每次模型回答都值得保存。可优先考虑跨任务仍有用途、来源可追溯且有维护责任的内容；临时日志、重复摘要、未核实猜测或原系统可以可靠查询的业务事实，需要分别评估。保存越多，检索噪声、撤销范围和维护成本也越大。

写入策略应区分同步准入和后台提取：前者影响当前响应，后者可能在原始条件已改变后才完成。后台任务也需要携带来源与预期版本，不能把“晚完成”当作“信息更新”。

## 来源标签不能由候选自己证明

| 建议记录的信息 | 用来解释什么 |
| --- | --- |
| 记忆 ID、主体与租户范围、用途 | 这条内容属于谁、用于什么 |
| 声明类型与核实状态 | 是陈述、观察、推断还是待核实候选 |
| 来源标识、来源版本与原文位置 | 怎样回查依据，有没有扩大来源支持 |
| 观察/生效/写入时间 | 事件何时发生、规则何时适用、系统何时保存 |
| 记忆版本、过期与维护责任 | 怎样更新、撤销和决定仍可使用 |

这是设计清单，具体字段应按用途取舍，本轮实验没有实现全部时间与维护字段。source_id="trusted" 或 confidence=0.99 都只是候选字段，不能自行建立真实来源。可信适配器需要把来源关联到实际会话、原记录或工具查询，并核对支持范围。

模型生成的摘要可能丢掉否定和时间条件；多个摘要反复互引，也不会形成独立证据。必要时回到原始记录，保留“未知”和冲突，不要用记忆把猜测逐步包装成事实。

## 来源核实与内容最小化一起设计

为了可追溯，不一定需要在每一层复制完整原文。可以保存受控来源引用、必要摘录或摘要与版本，但回查入口本身也要授权。摘要、哈希和来源 ID 各自提供不同证据：哈希可比较内容一致性，不能证明内容真实，普通哈希也不是匿名化保证。

记忆进入后续模型时仍是有来源的数据，不能自动提升为系统规则或新工具许可。相关边界见[工具授权与不可信结果](tool-authorization-and-untrusted-results.md)。

## 本地实验验证到哪里

[记忆治理实验](memory-governance-lab.md)使用可信来源夹具，把用户偏好、已确认工具观察和模型假设分开。模型假设只保存为 candidate，不进入默认事实检索；未经确认的工具观察、来源内容不匹配和试图把推断写成偏好的候选会被拒绝。

实验用来源摘要与候选原样内容相等来验证这个局部规则，不是自然语言蕴含判断，也没有运行模型提取或人工确认界面。工具观察的确认标记来自测试夹具，不能当作真实认证或业务核实服务。

自检：用户陈述、模型推断和工具观察都包含“喜欢中文”时，为什么仍应保存不同的来源与状态？一次工单创建成功应查询哪里，而不是从长期摘要里猜测？
