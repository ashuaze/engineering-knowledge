# TDD 与 BDD：测试写在前面，为什么仍可能做错需求

学习入口：先写断言再实现，所有检查都绿了，业务方却说结果不对。需要分别检查预期从哪里来、失败说明了什么，以及测试实际经过了哪些边界。

前置：[测试层次与替身](test-scopes-and-doubles.md)。本文核查 Kent Beck 与 Cucumber 的方法说明；订单、库存与场景均为纸面设计，没有编写或运行本篇的测试、[BDD](../../glossary/engineering.md#engineering.tdd) 工具或真实库存服务。

## TDD 把一次行为变化缩成短反馈循环

[Kent Beck 的 Canon TDD](https://newsletter.kentbeck.com/p/canon-tdd)从行为场景列表出发，每次选择一项变成具体可运行测试，使它及已有测试通过，再按需改善设计。先列场景不等于一次写完全部测试后才实现。

通常用红、绿、[重构](../../glossary/architecture.md#architecture.debt)描述循环：红阶段观察当前行为为何不满足预期；绿阶段做足以满足当前要求的实现；重构阶段在已有行为约束下调整设计。通过测试只覆盖已经表达的要求，不能借“最小实现”长期保留已知越权或错误状态。

测试因环境未启动、断言写错或依赖[认证](../../glossary/security.md#security.identity)失败而红，与缺少目标行为而红提供不同证据。需核对测试能运行到目标观察点；支持某些缺失接口的编译失败可以是开发步骤，但不能不加解释地当作业务反例已经验证。

## BDD 先让不同角色对行为达成理解

[Cucumber 的 BDD 说明](https://cucumber.io/docs/bdd/)把发现、表达和自动化连接起来。业务、开发与测试围绕具体例子澄清规则、疑问和结果；使用 Given/When/Then 语法只是表达方式，不等于协作已经发生。

TDD 侧重实现变化时的短反馈；BDD 强调从期望行为形成共同理解，两者可以配合，也不由使用哪种框架决定。业务验收例子可以由 API 或其他适当边界驱动，不必都走浏览器。

## 库存例子先揭示规则，再选择检查边界

假设某商品可用量为 2，购买数必须为正整数，本次讨论的是单次顺序操作：

| 输入或事件 | 期望业务结果 | 需要澄清的范围 |
| --- | --- | --- |
| 预留 1 件 | 接受，可用量变为 1 | 预留何时失效、释放怎样处理 |
| 预留 3 件 | 拒绝，可用量仍为 2 | 错误是否泄露其他库存信息 |
| 预留 0 或负数 | 拒绝且状态不变 | 类型、单位和最大数量 |
| 已有确定结果的同一操作再次提交，身份与参数相同 | 按约定返回原结果 | 操作身份、有效期及参数一致性 |
| 提交成功但响应丢失 | 可查询既有结果 | 不确定结果不能直接当作失败 |

这张表描述不同初始情形，第二行的 2 不是接着第一行的 1 继续运行。并发两次购买、事务冲突、过期释放与外部支付仍需另列场景，顺序例子不能证明它们正确。

[Example Mapping](https://cucumber.io/docs/bdd/example-mapping/)区分故事、规则、例子与待答问题。讨论中发现“重复预留”尚无定义时，应保留疑问和责任人，再形成契约，不能由一个方便写的断言悄悄决定业务。

## 断言结果，避免把偶然步骤固化为要求

“拒绝超量预留，库存不变”表达可观察结果；“必须调用某私有方法一次”可能只是实现细节。若调用次数本身关联有上限的重试、计费或协议约束，才应按对应契约检查。

本地内存替身便于快速探索规则，不包含真实数据库的隔离、持久性与网络不确定性。将目标行为放到能提供所需证据的边界，再用不同范围的检查互补，见[测试组合](test-pyramids-risk-portfolios-and-coverage.md)。

## 重构与需求改变分别处理

重构改善内部组织并保留声明的行为；修改“重复请求怎样处理”属于契约变化，应更新需求、例子、兼容与验收，而不只是把失败断言改成新实现当前的返回值。

未采用 TDD 的既有系统也可以补回归证据和逐步改善设计；方法名不能证明质量收益。评价需要观察反馈速度、遗漏风险与维护成本，本文未测量任何团队的效果。

## 自检

1. 场景列表、一次红绿循环和重构分别负责什么？
2. 测试因为认证配置错误而失败，为什么不能证明库存规则被检验？
3. Given/When/Then 文件存在，为什么不等于已经进行了 BDD？
4. 库存表的 1 件和 3 件例子是什么关系？它们为什么不证明并发正确性？
5. 改善内部结构与修改重复预留语义，应怎样分别处理？
